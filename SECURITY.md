# Security policy

This is the default policy for IOExtend repositories that do not carry their own `SECURITY.md`.

## Reporting a vulnerability

Please do not put the details of a security problem in a public issue. Use GitHub private vulnerability reporting on
the affected repository: open its Security tab and choose "Report a vulnerability". Include the version, the command
or API call, and a description of the problem. A file that triggers it helps, but do not send files with confidential
content; a crafted or cut-down file is usually enough.

If the repository does not offer "Report a vulnerability" (private reporting is not enabled there), open a public
issue that says only that you need a private channel, with no details of the problem, and a maintainer will contact
you.

You can expect an acknowledgement within a few days. Fixes are released as soon as they are verified, and the report
is credited unless you prefer otherwise.

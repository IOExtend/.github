# IOExtend Web

Локальная сборка инструментов IOExtend для просмотра, экспорта и понижения версии Revit. На вкладке «Просмотр» перетащите RVT или NWC на страницу либо выберите его через диалог. Открытую модель можно заменить, перетащив следующий файл прямо в окно просмотра.

Язык сайта и встроенного просмотрщика выбирается в шапке. В режиме «Авто» используется первый поддерживаемый язык из списка браузера. Если подходящего языка нет, используется английский. Ручной выбор сохраняется в браузере. При смене языка 3D-просмотр заново открывается из подготовленных данных с начальным ракурсом. Автономный HTML IOViewer имеет собственный переключатель и работает без сети.

Во время открытия видны текущий этап, примерный процент и время ожидания. Для RVT дополнительно видны счётчики
распакованных потоков, проходов разбора, блоков при восстановлении геометрии, блоков записей и имён,
прочитанных байтов и элементов, для которых построены сетки. При подготовке просмотра видны счётчики записанных
треугольников, обзорных страниц на каждом уровне и обработанных элементов. Веса этапов используются для оценки общего хода
работы. Обработку можно отменить кнопкой «Отменить».

## Запуск

Соберите проект с .NET 10 SDK и запустите статический сервер в папке с результатом.
Локальная сборка использует ветку `codex/rvt-segment-spooling` с чтением сегментов через временное хранилище. Чтобы подключить постраничный просмотр, подготовьте зависимости Node.js в исходниках IOViewer и передайте обе папки при сборке. [RvtIO PR #308](https://github.com/IOExtend/RvtIO/pull/308) · [IOViewer PR #81](https://github.com/IOExtend/IOViewer/pull/81)
[Прогресс чтения](https://github.com/IOExtend/RvtIO/pull/304), [ограничение временных результатов декодирования](https://github.com/IOExtend/RvtIO/pull/305), [чтение RVT из потока](https://github.com/IOExtend/RvtIO/pull/306), [чтение страниц RVT без копии потока](https://github.com/IOExtend/RvtIO/pull/307).

```powershell
dotnet publish -c Release -o publish-web -p:RvtIOProgressSource=/path/to/RvtIO -p:IOViewerSource=/path/to/IOViewer
python -m http.server 8976 --bind 127.0.0.1 --directory publish-web/wwwroot
```

Откройте [локальную страницу](http://127.0.0.1:8976/). Для GitHub Pages каталог `publish-web/wwwroot` можно использовать как артефакт публикации. В нём должны остаться `index.html` и папка `_framework`. [Документация GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

Для AOT-сборки разработчика используйте .NET 11 SDK с рабочей нагрузкой `wasm-tools`. Откройте статический сервер в каталоге `publish-web-aot/wwwroot`.

```powershell
dotnet publish -c Release -o publish-web-aot -p:IOExtendAot=true -p:RvtIOProgressSource=/path/to/RvtIO -p:IOViewerSource=/path/to/IOViewer
```

Профиль `-p:IOExtendPooledGc=true` включает экспериментальное групповое выделение блоков Mono SGen в
однопоточной сборке .NET 11 WebAssembly. Пул включается при сборке записей RVT и остаётся активным при
финализации. Для этого профиля добавьте флаг к команде AOT-сборки. Посетитель открывает её как обычную
статическую страницу в Chromium.

## Экспорт и даунгрейд

После публикации сайта соберите браузерные обработчики в тот же `wwwroot` с .NET 10 SDK. Для экспорта проверены RvtIO `9f9a43f` и NwcIO `d2c8469` (0.17.0). Для даунгрейда использовалась ветка `feat/revit-downgrade` RvtIO, коммит `7936c6e`.

```powershell
./operations/Publish.ps1 -Site ./publish-web/wwwroot -Build ./obj/site-tools -RvtIOProgressSource /path/to/RvtIO-export -NwcIOSource /path/to/NwcIO -DowngradeSource /path/to/RvtIO-downgrade
```

С .NET 11 SDK и рабочей нагрузкой `wasm-tools` к команде можно добавить `-ExportLargeHeap`. Этот профиль собирает обработчик экспорта с верхней границей линейной памяти почти 4 ГиБ.

Добавьте `-IOViewerSource /path/to/IOViewer`, чтобы использовать актуальную сборку автономного просмотрщика в HTML-экспорте RVT, RFA, NWC и NWD. Перед сборкой выполните `npm ci` и `npm run build` в каталоге `src/IOViewer/Viewer`. Прежний HTML Navisworks доступен отдельно среди дополнительных форматов.

Доступные форматы зависят от исходного файла. За один запуск можно получить несколько файлов. Дополнительные результаты Navisworks, например TimeLiner, требуют соответствующих данных в модели. Повторное сохранение Navisworks в NWC использует собственный формат записи NwcIO и отклоняет модели с линейными сетками. Для даунгрейда выберите исходный RVT или RFA. Сайт определит версию из потока `BasicFileInfo` и предложит более ранние версии из диапазона 2020–2026. RvtIO проверяет схему модели после запуска и создаёт отдельную копию с отчётом. Даунгрейд экспериментальный.

Обработчики читают исходные файлы по диапазонам. Для RVT и RFA используется `MONO_GC_PARAMS=soft-heap-limit=512m`, чтобы Mono раньше освобождал временные данные. Выходной файл собирается в памяти браузера. Предельный размер зависит от модели и доступной памяти.

Во время экспорта и даунгрейда видны этап, время обработки и объём чтения и записи. Счётчики ввода и вывода учитывают повторные обращения к файлу. Процент этапа появляется, если ядро сообщает выполненный и общий объём работы. При экспорте в несколько форматов отдельно видно, сколько обработок завершилось.

Браузерная проверка запускается через `node operations-smoke.cjs <локальный URL> <пример.nwc> <пример.rvt> <целевая-версия> [<пример-для-даунгрейда.rvt>]`. Она проверяет этапы и отмену, скачивание файлов, список версий, отчёт и отказ при повреждённых метаданных.
Проверка `node localization-smoke.cjs <локальный URL> <пример.nwc> [<пример.rvt>]` проверяет словари, режим «Авто», сохранение выбора, встроенный просмотр и скачанный HTML без сети.

Файлы в `wwwroot/profiles` содержат только таблицу классов, архивный заголовок и поля версии и сборки. Генератор в `operations/profile-tool` извлекает их из файлов целевых версий и сверяет заголовок со схемой. Полная модель и путь последнего сохранения в профиль не попадают.

При публикации интерфейс и загрузчики WebAssembly получают адреса с отпечатками содержимого. `prepare-web-release.mjs` записывает ресурсы до обновления `index.html`. Проверка `node release-smoke.cjs <wwwroot>` воспроизводит смешивание разметки и старых стилей на прогретом кэше и проверяет обычную перезагрузку.

## Как это работает

Весь разбор RVT и NWC и построение сцены должны выполняться в браузере пользователя. Посетителю должно
быть достаточно открыть страницу и выбрать файл. GitHub Pages используется для раздачи файлов приложения.
Модели RVT размером порядка 300 МБ и выше входят в целевой сценарий и требуют проверки на реальных проектах.

Браузер запускает RvtIO.Scene или NwcIO.Scene в отдельном Web Worker через .NET WebAssembly. Адаптер формирует IOScene, а IOViewer рендерит результат через WebGL 2. Файл модели остаётся в браузере. Для RVT с поддержкой OPFS распакованные сегменты, параметры и треугольные сетки временно лежат в приватном хранилище сайта. Ядро читает данные порциями. После сборки записей Revit временный файл сегментов освобождается перед построением сеток. На диске профиля браузера нужно свободное место для этих данных.

В сборке с исходниками IOViewer отдельный рабочий процесс преобразует треугольную сцену RVT в страницы геометрии и свойств. IOViewer запрашивает нужные диапазоны из локальных файлов пакета. Промежуточные файлы удаляются после построения страниц. Страницы остаются доступны до замены или закрытия модели. При отмене или ошибке удаляется папка текущего открытия. При следующем открытии сайт очищает оставшиеся папки, которые не используются другими вкладками.

До первого кадра новый фрейм просмотра остаётся прозрачным и недоступным для взаимодействия. Он находится в области просмотра, чтобы Chromium мог вызвать `requestAnimationFrame` внутри изолированного фрейма.

Для RVT сборщик мусора Mono настроен запускаться раньше через `MONO_GC_PARAMS=soft-heap-limit=512m`. Это порог для сборки мусора. Фактическое потребление памяти может быть выше.

Прототип обрабатывает одну модель за раз. Web Worker даёт .NET доступ к выбранному файлу диапазонами
окнами по 64 КиБ с кэшем до 16 МиБ. Пиковая память зависит от распакованных потоков, сложности геометрии
и временных данных ядра. При ошибках декодирования интерфейс сообщает, что часть элементов может отсутствовать.

У штатной сборки верхняя граница линейной памяти WebAssembly составляет 2 ГиБ. Для испытаний больших RVT
используется также AOT-сборка с границей почти 4 ГиБ. Измерения ниже относятся к указанным версиям прототипа.

## Проверка больших файлов

На локальных образцах браузер отрисовал постраничную геометрию, открыл свойства элементов и освободил временные данные после отмены. Синтетический RVT-контейнер на 10,01 ГиБ для проверки больших смещений сохранил исходную геометрию контрольной модели. Сложность реальной модели определяет расход памяти независимо от размера входного контейнера.

## Браузерная проверка

С установленным в среде Node.js пакетом Playwright запустите тест и передайте пути к локальным образцам. Тест проверяет перетаскивание, диалог выбора, замену и отмену, ошибки ввода и рендеринг обеих моделей.

```powershell
node smoke.cjs http://127.0.0.1:8976/ path/to/sample.rvt path/to/sample.nwc
```

Установите `IOEXTEND_REQUIRE_PAGED=1`, чтобы тест потребовал постраничный рендеринг для треугольной модели RVT.

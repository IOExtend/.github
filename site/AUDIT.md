## Сравнение с RvtIO main

Сборка Chromium WebAssembly с RvtIO `c54aa06` падала при ожидании фоновой задачи в `ElementBuilder.PostProcess`. С исправлением #310 браузер экспортировал Compact JSON публичного образца Revit за 47,5 с против 88,6 с в предыдущей сборке. Файлы совпали побайтно. Это один сравнительный прогон на одной машине.

Без API временного хранения из #308 крупный локальный образец достиг лимита линейной памяти WebAssembly сразу после распаковки. Базовый профиль сайта для больших RVT использует #308. [Нативные измерения в RvtIO #309](https://github.com/IOExtend/RvtIO/pull/309) · [Исправление WebAssembly в RvtIO #310](https://github.com/IOExtend/RvtIO/pull/310)

## Публичный образец Core Interior

В Chromium запустили два открытия демо `2024_Core_Interior.rvt` (33,7 МБ) на сайте rvt-rs и один прогон того же файла в IOExtend. SHA-256 файла совпал с каталогом демо. [Каталог демо](https://github.com/DrunkOnJava/rvt-rs/blob/eb268fdd22ced8e43bf8b2236b582f182880a2d8/docs/viewer-demos.json)

| Сборка | Интервал | Время | Линейная память WASM |
| --- | --- | --- | --- |
| rvt-rs, опубликованное демо | Клик до статуса Loaded, включая загрузку файла | 19,4 и 22,6 с | 308 МиБ |
| rvt-rs, опубликованное демо | Работа воркера после загрузки файла | 12,2 и 16,5 с | 308 МиБ |
| IOExtend, однопоточная AOT-сборка с #308 | Локальный файл до первого кадра | 225,6 с | 836,6 МиБ |

В GLB из rvt-rs прочитано 971 узел с геометрией и 38 812 треугольников. IOExtend вывел 1 314 элементов, 1 607 экземпляров и 41 032 треугольника в 300 страницах. В IOExtend восстановление геометрии стен заняло 80 с, финализация модели — 36 с.

rvt-rs разбирает модель в одном WASM-воркере, использует кэш распакованных разделов и отложенно читает сохранённые параметры выбранного элемента. Начальный разбор принимает содержимое всего файла, а просмотр получает готовый GLB. В IOExtend файл читается по диапазонам, а сцена и свойства передаются в страницы через OPFS.
